## 6. 性能代价，而非性能优化

以下都是 GitHub Actions 上的 **SwiftShader 软件渲染**，1920×1080、DPR 1，每场景 30 秒、连续三次。两版本是独立 CI 任务，不是同一物理 GPU 的受控 A/B 实验。

| 场景 | R06 中位 FPS（3 次） | R07 中位 FPS（3 次） | R07 p95 毫秒（3 次） |
| --- | --- | --- | --- |
| 整表环视 | 0.57 / 0.57 / 0.59 | 0.28 / 0.27 / 0.28 | 3750 / 3783 / 3767 |
| W16 隔离运动 | 0.47 / 0.48 / 0.47 | 0.46 / 0.46 / 0.46 | 2183 / 2183 / 2167 |

4× MSAA 在该软件后端造成了显著整表/拆解成本。因此 R07 是保留真实结果的画质候选，**不能认定它是相对 R06 的综合最佳版，更不能声称低端设备流畅**。原 R06 输入包未覆盖，Git 历史可恢复。合同目标中位 ≥55 FPS、p95 ≤25 ms 未满足；物理 GPU/手机既未证实通过，也不能用这些软件数字推算其帧率。

下一轮必须解决材质/形态复核与抗锯齿成本的取舍，保留当前固定相机证据，不得以删减活动部件、降低未声明分辨率或改预算来“通过”。这两项是未完成义务，不是可选未来扩展。
